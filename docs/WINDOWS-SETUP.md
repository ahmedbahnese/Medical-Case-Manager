# BSCH — إعداد Windows 7 والتشغيل التلقائي

## المتطلبات

| المكوّن | المتطلب |
|---|---|
| Windows | Windows 7 SP1 (32-bit أو 64-bit) |
| التطبيق | نسخة BSCH `ia32` المبنية من هذا المستودع |
| الشبكة | اتصال LAN ثابت إذا كان المستخدمون سيتصلون من أجهزة أخرى |

> هذه الحزمة تستهدف `ia32` حتى تعمل على Windows 7 بنسختيه. لا تحتاج أجهزة المستخدمين إلى تثبيت Node.js؛ فهو مضمّن في التطبيق.

## التثبيت

1. شغّل `BSCH-Setup-ia32-1.2.0.exe` بصلاحيات مناسبة.
2. لا تنقل مجلد التثبيت بعد انتهاء التثبيت.
3. شغّل BSCH مرة واحدة من حساب Windows الذي سيستضيف النظام.
4. يسمح التطبيق تلقائيًا بالعمل في الخلفية ويضيف نفسه إلى تشغيل Windows عند تسجيل الدخول.

## السلوك بعد الإصلاح

- عند بدء Windows وتسجيل الدخول، يبدأ التطبيق في وضع مخفي ويشغّل خادم API.
- إغلاق نافذة BSCH يخفيها إلى شريط النظام ولا يوقف الخادم.
- لإظهار الواجهة، انقر مرتين على أيقونة BSCH بجانب الساعة.
- لإيقاف الخادم نهائيًا، افتح قائمة أيقونة BSCH واختر **إغلاق التطبيق**.
- يمكن تعطيل التشغيل التلقائي من قائمة أيقونة BSCH.

## الوصول من أجهزة الشبكة

اعرف عنوان IP للخادم عبر:

```cmd
ipconfig
```

ثم افتح من أجهزة المستخدمين:

```text
http://عنوان-الخادم:8080
```

اسمح بالمنفذ TCP/8080 في جدار Windows الناري إذا طلبت الأجهزة الأخرى الاتصال. يمكن استخدام الملف الموجود في جذر المستودع:

```text
Allow-LAN-Port-8080.bat
```

ويجب تشغيله بصلاحيات المسؤول.

## بناء النسخة من المصدر

من جذر المستودع:

```bash
pnpm install
pnpm build:prod
cd electron
npm install
npm run build-installer
```

توجد الملفات الناتجة في:

```text
electron/dist-electron/
```

يتولى `prebuild-win` نسخ `better-sqlite3` وإعادة بنائه لإصدار Electron 22 ومعمارية `ia32`، ثم يتحقق من وجود ملف `better_sqlite3.node` قبل إنشاء المثبت.

## استكشاف خطأ SQLite

إذا ظهر الخطأ `Could not locate the bindings file` فلا تُنسخ DLL عشوائية من جهاز آخر. أعد البناء بالأوامر التالية:

```bash
cd electron
npm run prepare-native
npm run rebuild-native
npm run verify-sqlite
```

يجب أن يظهر:

```text
SQLite ia32: PE32 OK
```

ثم أعد إنشاء المثبت.
