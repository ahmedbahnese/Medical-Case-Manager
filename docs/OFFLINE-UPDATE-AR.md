# تحديث BSCH دون إعادة التثبيت

## الفكرة

تظل قاعدة البيانات في مجلد بيانات المستخدم، بينما تُحمّل ملفات التطبيق الجديدة داخل مجلد `updates` ثم يطبقها Electron عند التشغيل التالي. لذلك لا يحتاج المستخدم إلى إزالة المثبت أو إعادة إدخال إعدادات المستشفى.

## شكل الحزمة

أنشئ مجلدًا مثل `BSCH-Update-1.1.0` داخل مجلد التحديثات، ويجب أن يحتوي على البنية التالية:

```text
BSCH-Update-1.1.0/
├── api-server/
│   └── dist/
│       └── index.mjs
└── public/
    └── index.html
```

يمكنك وضع مجلد الحزمة أو ملف ZIP واحد. عند استخدام ZIP، يجب أن يحتوي الملف المضغوط على مجلدي `api-server/dist` و`public`. ضع ملفًا باسم `update-manifest.json` داخل مجلد `updates`:

```json
{
  "version": "1.1.0",
  "packageFile": "BSCH-Update-1.1.0.zip"
}
```

ولخيار المجلد استخدم:

```json
{
  "version": "1.1.0",
  "payloadDir": "BSCH-Update-1.1.0"
}
```

## موقع المجلد

في Windows، استخدم مسار بيانات التطبيق الظاهر في `%APPDATA%`، وغالبًا يكون:

```text
%APPDATA%\BSCH\updates\
```

إذا كان اسم مجلد المنتج مختلفًا في نسخة المؤسسة، ابحث عن مجلد `BSCH` الذي يحتوي على ملف `bsch.sqlite` ثم أنشئ داخله `updates`.

## التطبيق

أغلق التطبيق بالكامل ثم انسخ مجلد الحزمة وملف manifest إلى `updates` وشغّل BSCH. سيتحقق التطبيق من وجود الخادم والواجهة، وينسخ الحزمة إلى `update-runtime`، ويحفظ نسخة الإصدار المطبق، ثم يشغل النسخة الجديدة. لا تُحذف قاعدة البيانات ولا النسخة المثبتة الأصلية.

إذا كانت الحزمة ناقصة أو غير صالحة فلن تُطبق، ويستمر تشغيل النسخة السابقة. خذ نسخة احتياطية قبل أي تحديث كبير، ولا تستخدم ملفات تنفيذية أو سكربتات غير موثوقة داخل حزمة التحديث.

## بناء حزمة تحديث من المستودع

بعد بناء الخادم والواجهة:

```bash
pnpm build:prod
mkdir -p BSCH-Update-1.1.0/api-server/dist BSCH-Update-1.1.0/public
cp artifacts/api-server/dist/index.mjs BSCH-Update-1.1.0/api-server/dist/
cp -R artifacts/bsch/dist/public/* BSCH-Update-1.1.0/public/
```

أضف `update-manifest.json` كما في المثال، ثم انسخ ملف ZIP وملف manifest إلى إعدادات المؤسسة. سيبقى المثبت نفسه دون تغيير، وسيتم فك ZIP وتطبيقه تلقائيًا عند التشغيل التالي.

## ملاحظة توافق

نسخة Windows 7 ‏x32 مبنية على Electron 22.3.27، وهو آخر فرع رئيسي يدعم Windows 7. هذا لا يعادل استمرار الدعم الأمني للنظام القديم؛ يجب اختبار كل حزمة على جهاز المؤسسة قبل توزيعها.
